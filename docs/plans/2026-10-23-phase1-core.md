# Fleet Dashboard Phase 1 (Core): implementation plan

Spec: [`docs/specs/2026-10-23-fleet-dashboard-design.md`](../specs/2026-10-23-fleet-dashboard-design.md), §1, §2, §3 (agent
list, agent view, composer, full terminal, new agent, pause/resume) and §5 phase 1.
Repo: `~/Desktop/Public Repos/agent-fleet` (public, `github.com/wgrazz/agent-fleet`, branch `main`).

**In plain English:** the `fleet` terminal command learns to start agents with a chosen tool
and model, pause and resume them, and jot ideas. A small background program on the Mac
watches every agent and works out whether it is working, needs you, is done or has crashed.
It pings your phone when something changes, and serves a Mac-style web page where you can
see every agent, read its live screen, answer it with a tap, or open a full terminal. The
page installs on your iPhone's home screen through your private Tailscale network.

**Out of scope for phase 1** (later phases): folders, History, Chat view, Changes tab, usage
meters, ⌘K, the Ideas UI, Jarvis. `fleet idea` only stores the text in phase 1.

Execute the phases in order. Each phase is self-contained: read its references before
writing code. Commit at the end of each phase with
`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, and push to `origin main`.

## Phase 1: `fleet` CLI upgrades

**Files:** `fleet` (edit), `schema.sql` (new, at repo root).

1. **`schema.sql`**, idempotent (`CREATE TABLE IF NOT EXISTS`). The CLI (Python `sqlite3`)
   and the server (`node:sqlite`) both apply it on open, with `PRAGMA journal_mode=WAL`.
   - `profiles(name TEXT PRIMARY KEY, tool TEXT NOT NULL, model TEXT, effort TEXT, args TEXT, is_default INTEGER DEFAULT 0)`
   - `paused(id INTEGER PRIMARY KEY, name TEXT, tool TEXT, session_id TEXT, cwd TEXT, paused_at INTEGER)`
   - `ideas(id INTEGER PRIMARY KEY, list TEXT DEFAULT 'Brain Dump', text TEXT NOT NULL, done INTEGER DEFAULT 0, created_at INTEGER)`
   - `push_subs(endpoint TEXT PRIMARY KEY, sub TEXT NOT NULL)`

   DB path: `~/.fleet/fleet.db`. Create `~/.fleet/` mode 0700.
2. **`fleet json`** prints a JSON array of `show()`'s agents:
   `{pid, tool, age_s, session (tmux name or null), cwd, task, session_id, service}`.
   - Refactor `show()` so a single `rows()` function feeds both the table and the JSON
     output.
   - `session_id` comes from a new `session_id(tool, pid, cwd, started)` that implements the
     table above. Mark the "newest since start" heuristic with a `ponytail:` comment, like
     `codex_task` already does.
3. **`fleet new NAME [--tool T] [--profile P] [--model M] [--effort E] [--detach] [PROMPT...]`**
   - No `--tool`/`--profile`: keep the current behavior (shell in tmux).
   - With a tool:
     - Build the argv from the table and run it as
       `tmux new-session -d -s NAME -c CWD caffeinate -ims $SHELL -lic '<argv, shlex-joined>'`,
       so PATH comes from the login shell.
     - Then run `tmux set-option -t =NAME remain-on-exit on`.
   - `--profile` loads its row from `profiles`. Explicit flags override the profile's values.
   - `--detach` skips the attach (the dashboard uses this).
   - Validate NAME with `^[A-Za-z0-9._-]{1,40}$`.
4. **`fleet pause NAME`**
   1. Find the agent in session NAME via `rows()`.
   2. Insert `{name, tool, session_id, cwd}` into `paused`.
   3. Kill the session.
   4. If `session_id` is empty, refuse with "can't pause: no resumable session id".
5. **`fleet unpause ID|NAME`** runs `fleet new NAME --tool T --detach` with the resume argv in
   place of the first prompt (from the table), then deletes the `paused` row.
6. **`fleet idea [-l LIST] TEXT...`** inserts into `ideas` and prints `Added to <list>.`
7. **`fleet hook EVENT`**
   - Read stdin JSON, add `"event": EVENT` and `"tmux_pane": os.environ.get('TMUX_PANE')`.
   - POST it to `http://127.0.0.1:{port}/api/hook` with header `X-Fleet-Key` taken from
     `~/.fleet/config.json` (`{"port":7878,"key":"…"}`), using a 2 s timeout via
     `urllib.request`.
   - **Always exit 0, print nothing.**
8. **`fleet hooks install`** merges into `~/.claude/settings.json`, preserving every existing
   key and hook.
   - Events:
     - `UserPromptSubmit`, `PreToolUse` → `working`
     - `Notification` → `notify` (the server maps `notification_type`)
     - `Stop` → `done`
     - `SessionEnd` → `end`
   - Each entry is `{"type":"command","command":"<abs path to fleet> hook <event>","timeout":5,"async":true}`.
   - Idempotent: running it twice adds nothing. Back up the file to
     `settings.json.fleet-bak` first.
   - `fleet hooks uninstall` removes only entries whose command contains `fleet hook`.
9. **`fleet dash`** opens `http://127.0.0.1:7878/?key=…` with macOS `open`.
   `fleet dash install` and `fleet dash uninstall` are added in Phase 5.
10. **STATUS column** in `show()`:
    - GET `http://127.0.0.1:7878/api/agents` with the key and a 0.3 s timeout, then map
      `pid → status`.
    - Show `–` when the server is down. Add a `ponytail:` comment: status lives in the server;
      the CLI shows `–` without it.
11. **`selftest`** gains:
    - an argv-builder test for every tool × {prompt, model, effort, resume}
    - a `hooks install` merge test on a temp settings file (preserves existing hooks,
      idempotent)
    - a NAME validation test
12. **Update the README** command table, and the `__doc__` help text.

**Verify**
- `./fleet selftest` → `ok`.
- `./fleet new t1 --tool claude --detach "say hi"` → `tmux has-session -t =t1` succeeds,
  `./fleet json` lists it with a `session_id`, `./fleet pause t1` → session gone and a row
  in `paused`, `./fleet unpause t1` → back with the same conversation, `./fleet kill t1`.
  This uses a real Claude session. Keep the prompt trivial.
- `./fleet hooks install` twice → a `jq` diff against the backup shows the 5 entries were
  added once.

**Anti-pattern guard:** never print or log the key. `fleet hook` must never print to stdout,
because Claude would show it to the user.

## Phase 2: Server core (no UI)

**Files:**
- `dashboard/package.json` (`"type":"module"`, scripts `start`, `dev`, `test`, `build`)
- `dashboard/server/{index,config,db,agents,tmux,detect,state}.ts`
- `dashboard/test/detect.test.ts`
- `dashboard/test/fixtures/<tool>/<state>-N.txt`
- `.gitignore` adds `dashboard/dist/`

1. **`config.ts`** loads or creates `~/.fleet/config.json` (`port` 7878, `key` =
   `crypto.randomBytes(24).toString('hex')`) with mode 0600.
2. **`db.ts`** opens `~/.fleet/fleet.db` with `DatabaseSync` and execs `../../schema.sql`.
3. **`tmux.ts`** contains thin `execFile('tmux', …)` wrappers. Always target with `=NAME:`
   (exact match). Never build shell strings.
   - `capture(name, {ansi})`: `capture-pane -p [-e] -t =NAME: -S -200`
   - `sendText(name, text)`: `send-keys -t =NAME: -l text`, then `send-keys -t =NAME: Enter`
   - `sendKey(name, key)`: key ∈ {`Escape`, `Enter`, `Up`, `Down`, `1`…`9`}, allowlisted
   - `panes()`: `list-panes -a -F '#{session_name}\t#{pane_id}\t#{pane_pid}\t#{pane_dead}\t#{pane_dead_status}'`
4. **`agents.ts`** runs `execFile(FLEET_BIN, ['json'])` every 2 s and joins the result with
   `panes()` by session name. `FLEET_BIN` is the env value, defaulting to the repo's `fleet`.
5. **`detect.ts`**
   - `detect(tool, screen, prevScreen, msSinceChange): 'working'|'needs_you'|'done'|null`
     plus `quickReplies(screen): {key, label}[]`.
   - One table `DETECTORS: Record<tool, {needs: RegExp[], working: RegExp[], idle: RegExp[]}>`
     drives it. Generic rules:
     - Screen changed within 2 s → working.
     - The last 15 lines match `needs` (numbered menu `^\s*(❯\s*)?\d\.\s`, `\(y/n\)`,
       `Allow`, `Do you want to`) → needs_you.
     - Unchanged ≥ 5 s and `idle` matches → done.
   - `quickReplies`: lines `^\s*(?:❯\s*)?([1-9])\.\s+(.+?)\s*$` in the last 15 lines.
6. **Fixtures (required before tuning regexes).**
   1. For each tool, run it in a scratch tmux session in a throwaway directory
      (`mktemp -d`) and get it into each state:
      - **working:** a prompt that makes it run a shell command, captured mid-run.
      - **needs_you:** a permission prompt for a command not on the allowlist, e.g. `touch x`
        in default permission mode.
      - **done:** after it finishes a reply.
   2. Save each screen with `tmux capture-pane -p`.
   3. Do **not** run anything in the Optimal monorepo and do not run scraper code.
   4. If a tool can't be driven into a state, record that in the test as `it.todo` with the
      reason.
7. **`state.ts`** holds the per-agent state machine, keyed by tmux session name.
   - Inputs, highest priority first:
     1. a dead pane (`pane_dead=1`: exit status ≠ 0 → `crashed`, = 0 → `done`)
     2. a hook event less than 10 s old for Claude
     3. the detector
   - **Hooks → agent:** match `tmux_pane` to `pane_id`. Fall back to
     `session_id` == `fleet json`'s `session_id`.
   - **Notification mapping:** `permission_prompt`, `idle_prompt`, `elicitation_dialog` and
     `agent_needs_input` → needs_you. `agent_completed` → done. Everything else is ignored.
   - Emit `transition(agent, from, to)` events. Only transitions *into* needs_you, done or
     crashed are alert-worthy, and each fires once.
8. **`index.ts`** is a `node:http` server bound to `127.0.0.1:${port}`.
   - **Auth:** a valid `?key=` sets cookie `fleet_key` (HttpOnly, SameSite=Strict, Path=/,
     Max-Age 1 year, `Secure` when `x-forwarded-proto: https`) and redirects to strip the key
     from the URL. All `/api` and `/ws` requests require the cookie or the `X-Fleet-Key`
     header. Compare with `crypto.timingSafeEqual`. Anything else → 401.
   - **Routes (JSON in, JSON out):**

     | Route | What it does |
     | --- | --- |
     | `GET /api/agents` | `[{name, tool, pid, cwd, task, age_s, status, status_since, quick_replies, dead_status}]` |
     | `POST /api/agents` | `{name?, tool?, profile?, model?, effort?, prompt?}` → `fleet new … --detach`. Name auto-generated `<tool>-<4 hex>` if absent |
     | `POST /api/agents/:name/send` | `{text}` or `{key}` |
     | `POST /api/agents/:name/pause` | pause the agent |
     | `DELETE /api/agents/:name` | `fleet kill NAME` |
     | `GET /api/paused` | list paused sessions |
     | `POST /api/paused/:id/resume` | resume one |
     | `GET/PUT/DELETE /api/profiles[/:name]` | manage profiles |
     | `POST /api/hook` | from `fleet hook` |

   - Validate `:name` with the same regex as the CLI. Pass all arguments to `fleet` as an
     argv array.

**Verify**
- `cd dashboard && npm test`: detector tests pass on every fixture.
- `node server/index.ts` →
  - `curl -s 127.0.0.1:7878/api/agents` gives 401 without the key and a JSON array with it.
  - `./fleet new t2 --tool claude --detach "run: sleep 20 && echo done"` reaches `working`
    within 3 s and `done` after it finishes, checked by polling `/api/agents`.
  - Crash: `./fleet new t3 --tool claude --detach` followed by `kill -9 <claude pid>`
    → `crashed`.

**Anti-pattern guards:**
- No `exec`/`spawn` with `shell: true`.
- No regex on agent names to build commands.
- Hooks must never be able to 500 the server: wrap the handler, and on a bad body log once
  and return 204.

## Phase 3: Push + live screen + full terminal

**Files:** `dashboard/server/{push,ws}.ts`. Dependencies: `npm i ws web-push node-pty`.

1. **`push.ts`**
   - VAPID keys: `webpush.generateVAPIDKeys()` once, stored in `~/.fleet/vapid.json` (0600).
     Then `webpush.setVapidDetails('mailto:fleet@localhost', pub, priv)`.
   - Routes: `GET /api/push/key` → public key. `POST /api/push/subscribe` → upsert into
     `push_subs`.
   - On an alert-worthy transition, `webpush.sendNotification(sub, JSON.stringify({title, body, url: '/#/agent/NAME'}))`
     for every subscription:
     - title: `"<name> needs you"`, `"<name> is done"` or `"<name> crashed"`
     - body: the Notification `message`, else the last non-empty screen line, 120 chars
   - Delete a subscription when the response is 404 or 410. Log and ignore other errors.
2. **`ws.ts`**, using `new WebSocketServer({noServer:true})` with the auth check in the
   `server.on('upgrade')` handler.
   - `/ws/screen?name=N`: while connected, `capture(N, {ansi:true})` every 500 ms and send
     it only when it changed. Read-only. The client can't send.
   - `/ws/pty?name=N`: `pty.spawn('tmux', ['attach-session','-t',`=${N}`], {name:'xterm-256color', cols, rows, cwd: HOME, env})`.
     Pipe both directions. A client message `{"resize":[c,r]}` → `pty.resize`. On close,
     `pty.kill()`, which detaches; the agent keeps running.
   - Copy the node-pty usage from `node_modules/node-pty/README.md`, and the ws `noServer`
     upgrade example from `node_modules/ws/README.md`.

**Verify**
- A `node` script using `ws` connects to `/ws/screen?name=t2` and receives at least one frame
  containing the agent's prompt text.
- `/ws/pty`: send `"\x02d"` (tmux detach) and the socket closes while the session survives
  (`tmux has-session`).
- Push: subscribe a test endpoint. A `web-push` 410 response removes the row.

**Anti-pattern guards:**
- If `npm i node-pty` fails to build on Node 26, **stop and report**. Don't swap in
  another library without approval.
- The screen stream never accepts input. Only `/ws/pty` and `/send` do.
